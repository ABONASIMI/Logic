0. Pourquoi la récurrence ?

La récurrence sert à montrer une phrase qui parle de tous les entiers : « pour tout n ≥ 0, … ». Tu ne peux pas vérifier un par un (il y en a une infinité) → donc tu fais une preuve finie qui prouve quand même infini.

Image classique qu’on trouve dans plusieurs cours : il y a une rangée infinie de dominos. Si :

  1. le 1er domino tombe ;
  2. et si chaque domino fait tomber le suivant ;

alors tous tomberont.

Récurrence = ça.

1. Principe de récurrence (forme de base)

Énoncé (forme math info / Sorbonne) :

Soit P(n) une propriété dépendant d’un entier n. Si

  • (Initialisation) P(n₀) est vraie ;
  • (Hérédité) pour tout n ≥ n₀, P(n) ⇒ P(n+1) ;

alors P(n) est vraie pour tout n ≥ n₀.

Important : on ne « prouve » pas vraiment le principe en L1, on l’admet. Dans certains livres (genre Rosen), on le déduit du principe du bon ordre : « tout sous-ensemble non vide de ℕ a un plus petit élément ».

2. Recette à suivre à chaque exo

Quand le prof corrige, il veut lire plus ou moins ce squelette (dans TON TD aussi). Donc écris dans cet ordre :

  1. 1. Définition de P(n) : « Pour n ≥ …, on note P(n) : … »
  2. 2. Initialisation : « Pour n = …, P(n) est vraie car … »
  3. 3. Étape d’hérédité :
    • « Soit n ≥ … tel que P(n) est vraie » (hypothèse de récurrence) ;
    • « Montrons P(n+1) » (c’est l’objectif) ;
    • On part du membre gauche et on transforme jusqu’au membre droit, en utilisant l’hypothèse.
  4. 4. Conclusion : « Donc, par récurrence, P(n) est vraie pour tout n ≥ … »

Ne jamais écrire seulement : « par récurrence c’est vrai », sans avoir écrit les deux étapes.

3. Les différents types de preuves par récurrence

3.1 Récurrence simple

C’est celle que j’ai déjà écrite. On suppose seulement P(n) pour démontrer P(n+1).

3.2 Récurrence forte (vue dans les livres)

Dans Discrete Mathematics and its Applications (Rosen), on la note souvent « strong induction ». L’idée : pour prouver P(n+1), tu as le droit d’utiliser P(n), P(n−1), …, P(0).

On l’utilise dès qu’un objet est défini « en se cassant en morceaux » (facteurs premiers, algos récursifs…)

3.3 Récurrence à deux pas

Ex : suites de récurrence ordre 2 (Fibonacci). Tu dois prouver P(n) en utilisant P(n−1) et P(n−2).

3.4 Plus petit contre-exemple

C’est une façon « à l’envers » d’appliquer la récurrence qu’on retrouve dans certains sujets. On suppose qu’il existe un contre-exemple, on prend le plus petit, et on montre qu’il n’aurait pas pu exister.

4. Modèles d’exercices

4.1 Sommes (classiques des TD)

(1) Somme des n premiers entiers facile

Pour tout n ≥ 1 : 1 + 2 + ... + n = n(n+1)/2.

→ déjà fait, c’est le modèle de base.

(2) Somme des entiers impairs facile

Montrer que pour tout n ≥ 1 :

1 + 3 + 5 + ... + (2n − 1) = n²

P(n) : « 1 + 3 + ... + (2n−1) = n² »
Initialisation : n=1 → gauche = 1, droite = 1² = 1 → OK.
Hérédité : On suppose 1 + 3 + ... + (2n−1) = n². Alors 
(1 + 3 + ... + (2n−1)) + (2(n+1) − 1)
= n² + (2n+1)
= n² + 2n + 1
= (n+1)²
Donc P(n+1) vraie.
Conclusion : vrai pour tout n.

(3) Somme arithmétique générale moyen

Montrer que pour tout n ≥ 0 :

a + (a+r) + (a+2r) + ... + (a+nr) = (n+1)a + r·n(n+1)/2

Ici on applique exactement la même structure, c’est juste plus long à écrire.

(4) Somme géométrique moyen

Pour q ≠ 1, montrer par récurrence :

1 + q + q² + ... + qⁿ = (qⁿ⁺¹ − 1)/(q − 1)

4.2 Inégalités

Dans les TD de L1, on met souvent une ou deux inégalités pour t’obliger à ne pas faire que des égalités. La méthode est la même mais au lieu de « = » tu as « ≤ » ou « ≥ ».

(1) 2ⁿ ≥ n+1 facile

Déjà fait plus haut.

(2) n ≤ 2ⁿ pour n ≥ 0 facile

Très proche du précédent.

(3) (1 + 1/n)ⁿ ≤ 3 pour tout n ≥ 1 avancé

On peut le faire par récurrence en utilisant une majoration. Ça montre que parfois l’étape d’hérédité n’est pas juste “j’ajoute un terme”.

4.3 Divisibilité

Ici on reconnaît ton TD : le prof adore les preuves comme « 9 | (10ⁿ − 1) », « 3 | (2ⁿ − 1) », « 11 | (10ⁿ⁺¹ − 1)/9 », etc. Ça vient du fait que 10 ≡ 1 (mod 9).

(1) 9 divise 10ⁿ − 1 moyen

Déjà fait, mais je réécris en mode “copie à rendre”.

Propriété P(n) : « 10ⁿ − 1 est divisible par 9 ».
Initialisation : pour n=1, 10¹ − 1 = 9, divisible par 9. Donc P(1) vraie.
Hérédité : supposons P(n) vraie : il existe k ∈ ℕ tel que 10ⁿ − 1 = 9k. Alors 
10ⁿ⁺¹ − 1 = 10·10ⁿ − 1
= 10(10ⁿ − 1) + 9
= 10·9k + 9
= 9(10k + 1)
donc 10ⁿ⁺¹ − 1 est aussi divisible par 9. Donc P(n) ⇒ P(n+1).
Conclusion : par récurrence, P(n) est vraie pour tout n ≥ 1.

(2) 3 divise (2ⁿ − 1) moyen

On fait pareil :

  • P(n): « 2ⁿ − 1 ≡ 0 mod 3 »
  • n=1 → 2−1=1 pas bon → on commence à n=2.

Tu vois ici un point important : il faut choisir le bon point de départ. On n’est pas obligé de commencer à 0 ou 1 : on commence à l’endroit où la propriété devient vraie.

4.4 Formules binomiales

(1) Somme de C(n,k) moyen

On peut prouver par récurrence que :

∑k=0n C(n,k) = 2ⁿ

Ça vient du binôme de Newton, mais on peut le faire 100% récurrence.

4.5 Suites de type Fibonacci

Là on est dans la partie « parfois le TD te demande de prouver : Fₙ ≤ Fₙ₊₁ » ou « Fₙ ≤ 2ⁿ », etc. La méthode reste la même, mais l’étape d’hérédité utilise 2 hypothèses (ordre 2).

Exemple Fibonacci avancé

Soit (Fₙ) la suite définie par F₀ = 0, F₁ = 1, et Fₙ₊₂ = Fₙ₊₁ + Fₙ. Montrer que pour tout n ≥ 0 : Fₙ ≤ 2ⁿ.

P(n) : « Fₙ ≤ 2ⁿ ».
Initialisation : n=0 → F₀=0 ≤ 1 OK. n=1 → F₁=1 ≤ 2 OK.
Hérédité (double) : on suppose P(n) et P(n−1) vraies : Fₙ ≤ 2ⁿ et Fₙ₋₁ ≤ 2ⁿ⁻¹. On veut montrer P(n+1) : Fₙ₊₁ ≤ 2ⁿ⁺¹.

Or Fₙ₊₁ = Fₙ + Fₙ₋₁ ≤ 2ⁿ + 2ⁿ⁻¹ = 2ⁿ⁻¹(2 + 1) = 3·2ⁿ⁻¹. Et 3·2ⁿ⁻¹ ≤ 4·2ⁿ⁻¹ = 2ⁿ⁺¹. Donc Fₙ₊₁ ≤ 2ⁿ⁺¹.
Conclusion : vrai pour tout n.

5. Erreurs classiques

1. Ne pas écrire P(n)
Le correcteur ne sait pas ce que tu prouves.

2. Supposer P(n+1)
Tu n’as pas le droit. Tu supposes P(n) pour montrer P(n+1).

3. Oublier la conclusion
Tu fais tout le calcul mais tu ne dis pas « donc, par récurrence, … »

4. Mal choisir le point de départ
Certaines propriétés ne sont vraies qu’à partir de 2, 3, voire 5.

5. Changer de propriété en route
À l’étape n+1 tu dois prouver exactement la même forme qu’à l’étape n.

6. Ce que disent les autres livres (petite synthèse)

Si on regarde les livres de maths discrètes (Rosen, Grimaldi) ou les polys de Strasbourg / Paris / ULB, ils insistent sur 4 points :

  1. (a) Principe du bon ordre : toute partie non vide de ℕ a un plus petit élément → d’où l’induction.
  2. (b) Induction forte : version plus puissante mais même idée.
  3. (c) Induction descendante : on peut faire de n à n−1 quand on travaille à partir d’un grand entier.
  4. (d) Induction structurée : qu’on applique ensuite aux arbres, mots, programmes récursifs → ça c’est ton Ch4.

Dans certains livres d’info (par ex. Introduction to Algorithms de Cormen), quand ils prouvent la correction d’un algo récursif, c’est exactement une induction (souvent forte).

7. Petit lien vers Ch4 (induction structurelle)

Ch3 = on avance de +1 sur les entiers. Ch4 = on avance de +construction sur les objets (mot vide → mot ; liste vide → liste ; feuille → arbre).

Donc si tu as bien compris Ch3, Ch4 sera la même logique mais avec « cas de base » + « cas construit ».
