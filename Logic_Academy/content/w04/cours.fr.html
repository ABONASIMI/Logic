1. Le Problème SAT et la Forme Clausale

Le problème SAT (Satisfiabilité Booléenne) consiste à déterminer s'il existe une valuation satisfaisant simultanément un ensemble de clauses. C'est le premier problème historiquement prouvé NP-complet (théorème de Cook-Levin, 1971).

Définition 4.1 — Théorie Clausale et Clause Vide

Une formule en FNC est représentée comme un ensemble fini de clauses {{ \Sigma = \{C_1, C_2, \dots, C_m\} }}, où chaque clause {{ C_i }} est un ensemble fini de littéraux :

{{ C_i = \{l_{i,1}, l_{i,2}, \dots, l_{i,k}\} \quad \text{représentant} \quad l_{i,1} \lor l_{i,2} \lor \dots \lor l_{i,k} }}
  • Une clause est satisfaite par une valuation {{ v }} si au moins un de ses littéraux vaut 1 sous {{ v }}.
  • L'ensemble {{ \Sigma }} est satisfait si toutes ses clauses sont satisfaites simultanément.
  • La clause vide {{ \Box }} (notée {{ \{\} }}) : C'est une disjonction sans aucun littéral. Par définition, elle est toujours fausse (neutre pour {{ \lor }}). Si un ensemble de clauses contient {{ \Box }}, il est immédiatement insatisfiable.
  • L'ensemble vide {{ \emptyset }} : C'est une conjonction de zéro clause. Il est toujours vrai (neutre pour {{ \land }}). S'il ne reste plus aucune clause à satisfaire, la formule est satisfiable !

2. Les Règles de Réduction Fondamentales de DPLL

Règle 1 — Règle de la Clause Unitaire & Propagation Unitaire (UP)

Si {{ \Sigma }} contient une clause unitaire {{ C = \{l\} }} (réduite à un seul littéral {{ l }}) :

Pour que {{ \Sigma }} soit satisfiable, il est obligatoire que {{ l }} soit vrai (affectation {{ v(l) = 1 }}). On applique alors la simplification suivante à {{ \Sigma }} :

  1. On supprime toutes les clauses contenant le littéral {{ l }} (car elles sont déjà satisfaites).
  2. On supprime le littéral complémentaire {{ \neg l }} de toutes les autres clauses (car {{ \neg l = 0 }}, donc il ne peut pas aider à satisfaire ces clauses).

Cette simplification est répétée en cascade jusqu'à ce qu'il n'y ait plus aucune clause unitaire : c'est la propagation unitaire.

Règle 2 — Règle du Littéral Pur (PL)

Un littéral {{ l }} est dit pur dans {{ \Sigma }} s'il apparaît dans au moins une clause, mais que son complément {{ \neg l }} n'apparaît dans aucune clause de {{ \Sigma }}.

Justification sémantique : Poser {{ l = 1 }} satisfait immédiatement toutes les clauses contenant {{ l }}, sans risquer de falsifier aucune autre clause puisque {{ \neg l }} n'existe nulle part ! On peut donc éliminer toutes les clauses contenant {{ l }}.

3. L'Algorithme DPLL Classique

Algorithme DPLL(Σ)
  1. Propagation unitaire : Tant que {{ \Sigma }} contient une clause unitaire {{ \{l\} }}, simplifier {{ \Sigma }} par {{ l \leftarrow 1 }}.
  2. Test de terminaison immédiat :
    • Si {{ \Box \in \Sigma }} (clause vide générée) : Conflit ! Renvoyer UNSAT (retour arrière).
    • Si {{ \Sigma = \emptyset }} (toutes les clauses éliminées) : Succès ! Renvoyer SAT (modèle trouvé).
  3. Élimination des littéraux purs : Pour tout littéral pur {{ l }}, affecter {{ l \leftarrow 1 }} et supprimer les clauses le contenant.
  4. Branchement heuristique : Choisir une variable non encore affectée {{ p }} selon une heuristique (ex: {{ h_k }}).
    • Explorer la première branche : {{ DPLL(\Sigma \cup \{\neg p\}) }} (branche Faux en premier).
    • Si cette branche renvoie SAT, terminer avec succès.
    • Sinon (retour arrière / backtracking), explorer la seconde branche : {{ DPLL(\Sigma \cup \{p\}) }} (branche Vrai).

4. L'Heuristique {{ h_k }} (Sorbonne)

Lorsqu'aucune clause unitaire ni littéral pur n'est disponible, le choix de la variable de branchement est crucial. À la Sorbonne, le cours utilise l'heuristique {{ h_k }} :

Définition 4.2 — Heuristique {{ h_k(p) }}

Pour {{ k \ge 2 }} (taille de clause) et {{ p }} une variable propositionnelle :

{{ h_k(p) = \text{nbocc}(k, \Sigma, p) + \text{nbocc}(k, \Sigma, \neg p) }}

où {{ \text{nbocc}(k, \Sigma, l) }} est le nombre d'occurrences du littéral {{ l }} dans les clauses de taille {{ k }}.

Règle de sélection :

  1. On sélectionne la variable qui maximise {{ h_2(p) }} (les clauses de taille 2 sont les plus faciles à transformer en clauses unitaires !).
  2. En cas d'égalité, on départage avec {{ h_3(p) }}, puis {{ h_4(p) }}, etc.
  3. Si l'égalité persiste, on départage par ordre alphabétique du nom de la variable.
  4. Convention de branchement : On teste toujours la branche {{ p = 0 }} (Faux) en premier !

5. Format Standard DIMACS et Solveur Glucose

Les solveurs SAT industriels (comme Glucose) utilisent le format de fichier texte normalisé DIMACS : 

c Fichier DIMACS exemple
p cnf 3 4
1 2 0
-1 3 0
-2 -3 0
1 -3 0
  • Les lignes commençant par c sont des commentaires.
  • La ligne d'en-tête est p cnf n m où {{ n }} est le nombre de variables et {{ m }} le nombre de clauses.
  • Chaque clause est écrite sur une ligne, séparée par des espaces et terminée par un 0.
  • La variable {{ x_i }} est codée par l'entier {{ i }} ; sa négation {{ \neg x_i }} par l'entier négatif {{ -i }}.
